## 本轮实际落地

- `app.capture_xiaozhaoya` 枚举 Base 可见表，仅抓取同时包含“公司名称/招聘岗位”的完整招聘表；原始快照经 S1 校验后持久保存并拆分。
- 正常登录只发生在独立 Playwright 用户目录中；脚本不导出 Cookie 或令牌。首次未登录时自动跳过，不阻塞两张购买表。
- 增量停止条件为“连续两页均为已知 ID”或“整页早于 3 天”；抓取条数低于旧快照 80% 时拒绝覆盖。
- 优先使用企业投递链接，其次公告链接；链接缺失时保留条目并明确标注待补，避免静默丢信息。
- 校园招聘进入秋招；明确的公务员/事业单位/选调/三支一扶/军队文职进入公考。
- 真实页面响应字段 fixture 已覆盖解析、分类、链接优先级、宣讲会过滤和 S1 拆分测试。

## 后续优先级

1. 连续 7 天探测校招驿站，记录每天新增量、重复率、官网直链率。
2. 校招雷达 `jobs.json` 做周度兜底，并逐条验证 URL 协议与失效状态。
3. 校招Table 只做公开页探针；若翻页依赖登录则不接入。
4. 高校人才网独立建“高校招聘”数据集，避免把教师/博士后噪音重新混回公考表。
